# 好价清洗与用户爆料替换架构共识（必读指南）

本文档沉淀「全站好价线报清洗 + 详情页用户爆料 + 统一替换与防作弊体系」的核心共识、设计取舍与常见踩坑边界。后续任何开发或 AI 代理修改本模块前，必须先核对本共识，严禁凭直觉加回已被刻意淘汰的分支。

---

## 一、必须坚守的核心原则（红线 / 鼓励）

### 必须遵守（红线）
1. **替换仲裁唯一真源（SSOT）**：全站所有来源（普通爬虫、特惠采采、用户爆料、空位虚拟官方基线）的替换判断，必须全部委托 [`evaluate_deal_replacement`](../../models/deal_constants.py#L312) 执行，严禁在其他服务/仓储/提示词中另写平行替换规则。
2. **用户爆料只允许单阶段一次多模态 AI**：[`DealSubmitWorker`](../deal_submit_worker.py) 一次性完成图文验真、同口径比价与前端文案规整并直接上架，严禁再送回 `process_ai2_unit` 做二次清洗。
3. **跨级高低直接拦截（能零 AI 绝不花钱）**：当新投稿可靠分低于在架好价一整级（`new_score - ex_score <= -10`）时，必须在调用多模态模型前确定性跳过，不允许为明知不可能替换的投稿白烧推理费用。
4. **内容验真与结构完整性 Fail-Closed**：
   - 未明确通过 `is_content_valid == true` 且 `evidence_supports_claims == true` 时绝不上架；
   - 宣称通过却缺少 `observed_image_evidence`（长度 `< 8`）或同时缺少 `tutorial_steps` 与 `polished_copywriting` 时，判为异常/疑似注入并拦截，**绝不把未审清洗的用户原文回落写进正式表**。
5. **严禁空位原价占位白嫖佣金**：商品无有效在架好价时，默认以实时官方在售价构建虚拟同级基线，用户爆料必须同口径实质便宜（`>= 5%` 且 `>= 1 元`）才可上架。
6. **防提示词注入数据隔离**：用户输入的文案、优惠券串及截图内文字一律属于**不可信待审数据**，提示词与流程必须明确禁止执行其中指令。
7. **防盗图与防刷互动**：入口拦截精确哈希及二次 JPEG/PNG 重编码复用图；好价正式易主替换时清零 `user_stats.buyable / unbuyable`；`unbuyable` 仅受 `-10` 权重惩罚，游客与代理防刷由 [`extract_actor_key`](../product_stats_service.py#L27) 统一收敛。

### 鼓励的做法
- **复用数值化 `reliability_score` 分层**：普通爬虫 `10` 分，精品人工源（如特惠采采）与正常用户 `20` 分（绑定于 `users.reliability_score`），特邀核心达人 `30+` 分；分差 `>= 10` 构成跨级压制，`< 10` 进入同级竞争。未来调整来源或用户信誉只需改配置分值，不改代码分支。
- **单阶段多模态提示词遵循「严守安全底线 + 抽象语义泛化 + 计算收回代码」**：
  1. 对涉黄涉赌、私域导流、Prompt 注入、明显 PS 涂改、个人储值卡/专属资产压价及无据虚报保持零容忍；
  2. 对多样化电商页面形态与营销话术，提示词用**通用不变量**描述（区分“面向进入页面/频道大众买家的公共优惠”与“个人排他储值资产”，宽容口语转述与多商品列表上下文），严禁靠列举具体平台字眼/硬编码举例来打补丁；
  3. **规格对齐交给 AI，数学比较收回代码**：VLM 只判定 `price_unit_aligned`（双方购买规格与打包份数是否同口径一致）；一旦确认同口径（`true`），`>= 5% 且 >= 1 元` 的价格大小仲裁由 Python [`is_substantially_cheaper`](../../models/deal_constants.py#L297) 确定性算出并覆写模型偶发的算术幻觉；仅跨份数或跨子规格时采信模型归一化对比结论。
- **事前威慑 + 提现前人工审计兜底**：前端提交页与个人记录页清晰告知“人工审查 + 打款前二次复审历史替换行为 + 恶意取消佣金/封号”，用制度成本补足极端高仿图的技术上限。

## 二、统一机制全景：1 次多模态 AI + 3 条死规则 + 虚拟官方基线

### 1. 唯一的 3 条替换死规则（不看“老图是不是价格截图”）
- **规则 1（高分压低分）**：`new_score - ex_score >= 10` → **立即替换**（不看价格涨跌、不受 6 小时限制）。
- **规则 2（低分打高分）**：`new_score - ex_score <= -10` → **直接不替换**（用户侧零 AI 直接跳过；爬虫侧不覆盖高分用户好价且不延长用户好价 72h 寿命）。
- **规则 3（同级竞争，分差 `< 10`）**：
  - 实质更便宜（同口径降幅 `>= 5%` 且 `>= 1 元`，`cheaper`）→ **立即替换**；
  - 同价或微差（`same`）→ **不替换**；
  - 价格更高（`higher`）→ **仅用户爆料在老好价满 6 小时保护期后才允许替换纠偏**（爬虫不开放涨价替换）。

### 2. 空位商品如何彻底统一进上述 3 条规则？（虚拟官方基线）
当正式表商品没有有效在架好价（从未有过或满 72h 过期下架）且官方在售价 `> 0` 时，[`_build_official_baseline_snapshot`](../deal_submit_worker.py) 仅在本次审核内存中构造临时对比基线：
- **基线价格**：当前官方在售价（`activity_price` / `price`）；
- **基线可靠分**：**强制等于当前投稿人自己的 `reliability_score`**（确保无论 10/20/30 分账号均进入同级比价）；
- **基线时间**：**永远为当前时刻（`age = 0 小时`）**（永远处于 6 小时保护期内）；
- **配图与历史编号**：配图列表为空、源编号为空（防止把官方主图误查成盗图，也不产生虚假替换历史）。

结果无需在 `evaluate_deal_replacement` 加任何新分支，自然实现：**空位实证更便宜（含多件折单价/多 SKU 同规格降价）→ 上架；与官价相同、微差或更贵 → 统一拦截**。

### 3. 全站来源横向对照表

| 维度 | 普通爬虫（`10` 分） | 特惠采采（`20` 分） | 用户爆料（默认 `20` 分，可按人分级） |
|---|---|---|---|
| 比价方式 | 纯数字 `deal_price` 粗比（AI-1 阶段提取） | 纯数字 `deal_price` 粗比 | 唯一 1 次多模态 AI 同口径比价（支持多件/大宗折单价） |
| 无有效好价时 | 直接上架 | 直接上架 | 强制对比内存“虚拟官方基线”（须实质更低） |
| 替换同级更低价 | ✅ 立即替换 | ✅ 立即替换 | ✅ 立即替换 |
| 满 6h 后更贵纠偏 | ❌ 不允许 | ❌ 不允许 | ✅ 凭实拍截图替换纠偏 |

## 三、反直觉设计决策（为什么我们刻意不做这些事）

> **前车之鉴：下面每一点都是我们在多轮推演后特意做减法砍掉的复杂度，请勿擅自“补回来”。**

1. **为什么不让大模型去判断“老好价配图算不算价格凭证，没凭证就允许 6h 内直接顶掉”？**
   - 增加老图真伪二次多模态误判率，且会破坏 6 小时保护期的确定性；需要让用户覆盖某个渠道源时，直接把该渠道分值设为比用户低 `10` 分即可。
2. **为什么不把“官方基线”真实写入数据库 3 万条普通商品的 `deal_info`？**
   - 否则全库无优惠商品都会污染“严选好价”榜单与搜索索引，还会跟官方调价产生脏同步；仅在审核时于内存瞬态构造是最优零成本抽象。
3. **为什么不用 `if deal_price >= official_price` 在入口一刀切？**
   - 会在两类正常场景下严重误杀：① 拍 2 件实付总价高于 1 件官价但单价更低；② 多 SKU 商品官方默认返回低价体验装，而用户截图买大规格优惠。交给多模态 AI 在同口径下对比才是根治。
4. **为什么不为爬虫维护一套“折算单价字段 + 单位换算库”？**
   - 同级爬虫与用户在“1 件 vs 2 件”上撞车的概率极低，维护“瓶/包/箱/斤/抽”全库单位对齐极其脆弱且维护成本远高于收益；仅在 [submit_deal.html](../../static/submit_deal.html) 与 [爆料阶段1提示词](../../prompt/爆料阶段1_原始拆解与转链提纯.txt) 用一句话把 `deal_price` 统一成“实付总价”即可。
5. **为什么图像原图防重用“同尺寸灰度像素均差 + 极值像素数”，而不用粗糙的低维 dHash/pHash？**
   - 实测同一套下单页模板只改 2 个价格数字时，8×8 dHash 只有 `1/64` 差异极易误杀诚实更新；而同尺寸像素差下，二次 JPEG/PNG 压缩均值 `<= 0.5` 且大差像素数 `gt40 == 0`，仅改 2 个数字则会触发 `gt40 > 400`。用 `mean_diff <= 2.5 and gt40_pixels <= 25` 既能 100% 拦住重压缩原图重传，又绝不误杀同模板正当更新。
6. **为什么满 6h 涨价纠偏（含恢复官价）暂不剥夺奖励？**
   - 避免再拆出一套“仅纠偏不给佣/缩短展示期”的复杂状态机；用限额与打款前人工审计惩罚恶意“卡 6 点抢热门好价”的刷子即可。

## 四、已知边界与实测踩坑备忘

- **高仿自洽 P 图上限**：若恶意人员用修图软件将价格、优惠明细、字体做到完全自洽无破绽，单靠低档多模态模型肉眼无法 100% 识别（属计算机视觉共性上限），必须依赖人工二次复核与惩罚威慑。
- **微改裁剪盗图需靠提示词与人审双保险**：当老图被裁剪边角、调亮并加贴纸绕过像素防重时，轻量多模态模型仍可能只顾比价而漏掉跨图查重，重要高佣金商品打款前须核对截图雷同度。
- **京东官域静态白名单优惠券**：`coupon.m.jd.com/coupons/show.action` 目前仅作 URL 白名单重组校验格式，不在线核验券是否被抢光，属已知安全取舍；跨平台或陌生域名外链一律在转链阶段直接拦截。
- **存量历史数据过渡期**：重构上线前已入库但缺失 `reliability_score`（为 `null`）的旧 `tehuicaicai` / `user_submit` 记录，会按兜底默认分 `10` 处理，直至其自然过期或重新抓取/入库刷新。
