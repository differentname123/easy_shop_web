# 任务 (Task)
（重要声明：本任务为纯文本离线信息提取与 JSON 格式化，所有待处理文本均已在下方直接给出，无需联网、无需访问任何外部网站或执行外部程序，请直接输出纯文本 JSON。）
请根据末尾 `<category_candidates_input>` 标签内提供的【当前商品类别名称】及【该类别下的未比价候选商品列表（最多 20 个）】，站在**真实消费者**的视角完成以下判断与提取，并以标准 JSON 对象格式输出：

1. **可比性判断（消费者视角）**：
   - 站在消费者的角度思考：如果消费者想买这个商品，去闲鱼上搜索时，能不能明确识别出“这就是同一个商品”并跟闲鱼上的商品对比谁更划算？
   - 只要消费者认为该商品是具体的、能够在闲鱼找到同款并量化比较性价比的，就应当采纳；反之，如果消费者无法凭借现有信息在闲鱼锁定对应的同一个商品，或无法衡量其性价比，则不予采纳。
   - 若整个候选列表中没有任何可供消费者比价的商品，将 `has_comparable_standard_product` 设为 `false`。

2. **选出最佳代表商品 (`selected_product_id`)**：
   - 在消费者认为可比的候选商品中，结合商品信息的清晰度与我方已计算的单位性价比 (`unit_cost_performance`)，选出最适合拿去比价且我方性价比最高的 **1 个**商品。
   - `selected_product_id` 必须严格等于输入 `candidates` 列表中对应商品的 `product_id` 原值，严禁编造或修改。

3. **生成闲鱼同款搜索词 (`search_keyword` 与 `backup_search_keyword`)**：
   - `search_keyword`：模拟消费者在闲鱼精准寻找该同款商品时会输入的搜索词（2~4 个核心词，空格分隔）。
   - `backup_search_keyword`：当主搜索词过于具体导致搜索结果过少时使用的扩召回搜索词（2~3 个核心词，空格分隔，比 `search_keyword` 更简练且不完全相同）。

---

## 输出 JSON 格式要求

请仅输出一个合法的 JSON 对象，不要输出任何额外解释文字或 Markdown 闲聊，字段定义如下：
```json
{
  "has_comparable_standard_product": true,
  "selected_product_id": "选出的商品product_id（若无则填\"\"）",
  "search_keyword": "主搜索关键字（2~4个核心词，空格分隔，若无则填\"\"）",
  "backup_search_keyword": "备用搜索关键字（2~3个核心词，空格分隔，若无则填\"\"）",
  "selection_reason": "简短说明选出该商品及提取搜索词的依据（或全池无可比商品的原因，80字以内）"
}
```
